## Summary

A Microsoft Dynamics 365 / Fluent UI-styled knowledge portal hosted on Azure Static Web Apps. Content (documents, videos, images) is stored in Azure Blob Storage with metadata indexed in a `content-index.json` manifest file living in this GitHub repository. The manifest is auto-generated by a GitHub Action on every content-affecting commit. All users browse and search without authentication; content managers authenticate via Microsoft Entra ID to upload, edit, and delete resources.

---

## Architecture

### Hosting
- **Azure Static Web Apps (SWA)** — serves the React SPA and Azure Functions API routes in a single deployment unit. No separate App Service required.

### Services
| Service | Role |
|---|---|
| Azure SWA | Frontend hosting + Functions API routes |
| Azure Blob Storage | Binary file storage (private container, SAS URLs per request) |
| GitHub repo | `content-index.json` manifest — single source of content metadata |
| GitHub Actions | Auto-regenerates manifest on every commit touching `/content/` |
| Microsoft Entra ID | Authentication via SWA built-in auth (zero custom auth code) |

### No database
Metadata lives entirely in `content-index.json`. No Cosmos DB or SQL for v1.

### State management

## Data Flows

### Read flow (all visitors)
```
App mounts
  → GET /api/manifest  →  returns content-index.json from GitHub raw URL
  → stored in ManifestContext
  → all browse/search/filter operates in-memory (no further network calls)

ResourceDetailPage for :id
  → resource looked up in manifest (instant)
  → GET /api/resource/:id/url  →  Azure Function returns short-lived Blob SAS URL
  → InlineViewer and Download button use that SAS URL
```

### Upload flow (Content Manager)
```
User submits MetadataForm + file
  → POST /api/upload  (multipart: file + metadata JSON)
  → Azure Function:
      1. Validates file type (PDF/DOCX/PPTX/XLSX/MP4/WEBM/JPG/PNG/GIF/SVG)
         and size (≤ 100 MB)
      2. Uploads file to Azure Blob (private container)
         Blob name: {uuid}.{ext}
      3. Reads current content-index.json from GitHub API
      4. Appends new resource entry (id, title, description, category,
         type, blobName, fileSize, uploadDate, uploadedBy, featured)
      5. Commits updated manifest back to GitHub
      6. Returns new resource ID
  → GitHub Action fires on commit → regenerates + re-sorts manifest
  → Portal re-fetches ManifestContext
  → Resource appears in gallery within ~30 seconds
```

### Edit / Delete flow (Content Manager)
```
PUT /api/resource/:id
  → Function reads manifest → patches entry → commits back to GitHub

DELETE /api/resource/:id
  → Function removes entry from manifest + commits back
  → Deletes Blob file from storage
  → GitHub Action regenerates manifest
```

### Auth flow
```
User clicks "Sign In"
  → redirect to /.auth/login/aad  (SWA-managed)
  → Entra ID handles credential challenge
  → SWA sets session cookie; GET /.auth/me returns { userDetails, roles }
  → React reads roles on app mount
  → /upload and /manage render only if roles includes "content-manager"
  → Azure Functions verify x-ms-client-principal header server-side
```

### Search flow (client-side)
```
User types ≥ 3 chars
  → debounced 200ms
  → filter ManifestContext in-memory: title + description + category
  → results render < 1 second
  → URL updated to /search?q=... for shareability
```

### Component Style Rules
- **Cards:** White, `1px solid #E1DFDD`, `4px` radius, subtle `8px` shadow on hover. Flat by default — Fluent UI aesthetic.
- **Buttons:** Primary = `#0078D4` fill + white text. Secondary = white fill + `#0078D4` border. `2px` radius (not pill).
- **Type badges:** Teal (`#00B4D8`) for Video, blue (`#0078D4`) for Document, green (`#498205`) for Image.
- **TopNav:** White, `1px` bottom border `#E1DFDD`, `48px` height — matches Dynamics 365 shell.
- **Spacing:** 4px base grid. Common values: 8, 12, 16, 24, 32, 48px.
- **Grid:** 12-column CSS Grid. Cards: 3-col desktop → 2-col tablet → 1-col mobile.
- **Icons:** Fluent UI System Icons (open-source SVG set).

### GitHub Abstraction Rules
- File paths never displayed — friendly titles only
- Dates shown as `"April 18, 2026"` not commit SHAs
- Categories shown as labels, never folder paths
- Download triggers SAS URL, not a `raw.githubusercontent.com` link
- Upload UI uses drag-and-drop, not git terminology

## Key Constraints

- Maximum file upload: 100 MB (FR-010)
- Supported file types: PDF, DOCX, PPTX, XLSX, MP4, WEBM, JPG, PNG, GIF, SVG (FR-003)
- Search results within 1 second (SC-002)
- Page load within 2.5 seconds (SC-003)
- Resource live within 60 seconds of upload (SC-004)
- Responsive: 320px → 2560px (SC-005)
- Auth: Microsoft Entra ID only; no guest/local accounts in v1
- Browser support: Edge, Chrome, Firefox, Safari (latest two versions)
- No i18n in v1; English only
